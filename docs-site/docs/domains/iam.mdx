# Домен IAM

**IAM** — домен идентичности и доступа: кто есть кто в платформе и что кому можно. Он закрывает
задачу «управляемый доступ к ресурсам с иерархией владения»: Account — верхний контейнер владения,
Project — рабочая единица внутри него, User / ServiceAccount / Group — субъекты, Role описывает
набор прав, AccessBinding связывает роль с субъектом на конкретном scope. Отдельно IAM выступает
как PDP (policy decision point) — `AuthorizeService` отвечает на вопрос «можно ли subject'у выполнить
действие».

Пакет — `kacho.cloud.iam.v1`, REST-префикс — `/iam/v1`. ID-префиксы: `acc`, `prj`, `usr`, `sva`,
`grp`, `rol`, `acb`.

Role описывает права через `rules` (наборы `resources` / `verbs` / `resource_names` / `module`) —
K8s-подобная rules-модель. AccessBinding связывает роль с одним или несколькими субъектами на scope
(cluster / account / project или конкретный ресурс).

## PDP — AuthorizeService

`AuthorizeService` — точка принятия решений об авторизации. Синхронные запросы к модели прав.

| RPC | REST | Назначение |
|---|---|---|
| `Check` | `POST /iam/v1/authorize:check` | Разрешено ли действие subject'у на объекте |
| `BatchCheck` | `POST /iam/v1/authorize:batchCheck` | Пакетная проверка нескольких пар |
| `ListObjects` | `POST /iam/v1/authorize:listObjects` | Объекты, доступные subject'у (для list-фильтрации) |
| `ListSubjects` | `POST /iam/v1/authorize:listSubjects` | Субъекты с доступом к объекту |
| `ExpandRelations` | `POST /iam/v1/authorize:expandRelations` | Раскрытие графа отношений |
| `WhoAmI` | `GET /iam/v1/me` | Идентичность текущего subject'а |

**PermissionCatalogService** — `ListPermissionCatalog` (`GET /iam/v1/permissionCatalog`): канонический
каталог прав платформы, собираемый из authz-аннотаций `.proto` (см. [Авторизация](/infra/authz)).

## Internal-сервисы (:9091)

| Сервис | Ключевые RPC | Назначение |
|---|---|---|
| `InternalIAMService` | `Check` · `LookupSubject` · `RegisterResource` · `UnregisterResource` · `WriteCreatorTuple` · `PollSubjectChanges` | Per-RPC authz-gate для всех сервисов + регистрация owner-таплов ресурсов |
| `InternalAuthorizeService` | `WriteTuples` · `ReadTuples` · `ReloadModel` · `GetFGAStoreInfo` | Прямое управление таплами и моделью авторизации |
| `InternalClusterService` | `Get` · `GrantAdmin` · `RevokeAdmin` · `ListAdmins` | Cluster-scope и cluster-admin гранты |
| `InternalUserService` | `UpsertFromIdentity` · `Get` · `OnRecoveryCompleted` | Синхронизация пользователей из провайдера идентичности |
| `InternalIamHooksService` | `TokenHook` · `RefreshTokenHook` | Хуки обогащения токенов на выдаче/refresh |
| `InternalSessionRevocationsService` | `Revoke` · `IsRevoked` · `ListByUser` | Отзыв сессий |
| `InternalOperationsService` | `ListIamOperations` | Служебный список операций домена |

:::info IAM зовут все сервисы
`InternalIAMService.Check` — authz-gate, который вызывает каждый RPC каждого домена (см.
[Авторизация](/infra/authz)). IAM — leaf-домен: он не зависит ни от одного другого сервиса.
:::
