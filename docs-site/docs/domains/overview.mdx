# Обзор доменов

Контракт Kachō разбит на доменные пакеты `kacho.cloud.<domain>.v1`. Каждый домен — самостоятельная
область платформы со своими ресурсами и сервисами; между собой домены общаются по API (никаких
общих БД или cross-domain FK). Эта страница — карта доменов и указатель по каталогу.

## Карта владельцев ресурсов

Каждый тип ресурса принадлежит **ровно одному** домену — он и есть его канонический API. Consumer'ы
ссылаются по id (TEXT, без FK) и валидируют ссылку через API владельца.

  <thead><tr><th>Ресурс</th><th>Владелец</th></tr></thead>

    <tr><td>Region · Zone</td><td>Geo</td></tr>

## Общие правила чтения каталога

- **Публичные vs internal сервисы.** `<Service>` — tenant-поверхность (через api-gateway).
  `Internal<Service>` — cluster-internal (:9091): admin-CRUD справочников, инфра-данные, hooks и
  service-to-service обмен. Internal-методы не публикуются на внешний TLS endpoint.
- **Sync vs async.** `Get`/`List` и специализированные списки — синхронные. Мутации и action-RPC
  возвращают [`Operation`](/infra/operation) (кроме отдельных internal-CRUD, отдающих ресурс сразу).
- **REST-пути** в таблицах — это `google.api.http` из `.proto`. gRPC-имя метода указано рядом.
