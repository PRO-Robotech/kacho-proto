# Домен VPC

**VPC** — сетевой домен платформы: приватные сети и всё, что к ним крепится. Он закрывает задачу
«изолированное сетевое пространство проекта с управляемой адресацией, маршрутизацией и
фильтрацией». Network задаёт границу изоляции, Subnet нарезает её на подсети с CIDR-блоками,
Address управляет IP-адресами, SecurityGroup фильтрует трафик, RouteTable задаёт маршруты, Gateway
и NetworkInterface подключают ресурсы к сети.

Пакет — `kacho.cloud.vpc.v1`, REST-префикс — `/vpc/v1`. ID-префиксы: `net`, `sub`, `adr`, `rtb`,
`sgr`, `gtw`, `nic`.

## GatewayService · NetworkInterfaceService

Оба — стандартный CRUD-набор (`Get`/`List` sync, `Create`/`Update`/`Delete` async, `ListOperations`
sync) под `/vpc/v1/gateways/…` и `/vpc/v1/networkInterfaces/…` соответственно.

## Internal-сервисы (:9091)

| Сервис | Назначение |
|---|---|
| `InternalAddressPoolService` | Admin-CRUD пулов адресов (AddressPool) + cidr-блоки + bind как network-default. Публикуется только на internal mux |
| `InternalAddressService` | IPAM-аллокация (`AllocateInternalIP`/`AllocateExternalIP` v4/v6) и reference-учёт адресов для consumer-сервисов |
| `InternalNetworkService` | Служебные операции над сетью (default SG, internal-проекция сети) |
| `InternalResourceLifecycleService` · `InternalWatchService` | Потоки событий (`Subscribe` / `Watch`) для операторов data-plane |

:::warning AddressPool — только internal
`AddressPool` (`/vpc/v1/addressPools/…`) — admin-ресурс на cluster-internal листенере; на внешний
endpoint не публикуется. Его CRUD возвращает ресурс синхронно, а не через `Operation`.
:::
